# Mode ketiga "Auto" (OpenCode + Claude Code) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tambahkan mode tersimpan ketiga **⚡ Auto** (nilai tersimpan `autopilot`) untuk kedua engine, agar shell/jaringan dikerjakan tanpa kartu izin, dengan aturan `deny`, Plan read-only, dan file rahasia tetap otoritatif.

**Architecture:** Satu kosakata mode (`build`/`plan`/`autopilot`) di `src/modes.js`, diteruskan ke OpenCode sebagai `OPENCODE_CONFIG_CONTENT.permission` (lewat `permissionConfig`/`mergePermission`) dan ke Claude Code sebagai `--permission-mode auto`. Lapisan UI (`engine-caps.js`, `statusline.js`, `index.html`, `composer.js`) memakai kosakata yang sama.

**Tech Stack:** Node >= 20, ES module, `node:test` + `node:assert/strict`, UI statis di `public/`.

**Spec:** `docs/superpowers/specs/2026-11-20-mode-auto-design.md`

## Global Constraints

- **Nilai tersimpan mode baru adalah `autopilot`**, bukan `auto`. Label UI tetap **⚡ Auto**.
- `migrateMode('auto')` **tetap** `{ mode: 'build', legacyMode: 'auto' }` (nilai lama tidak boleh menjadi Auto). `migrateMode('autopilot')` → `null`.
- Auto = 3 tool OpenCode (`edit`/`bash`/`webfetch`); **tidak** menyentuh tool `read`. Deny user tetap menang.
- Claude memakai `--permission-mode auto`, **bukan** `bypassPermissions`/`--dangerously-skip-permissions`.
- Plan tetap read-only di kedua engine.
- Teks yang tampil ke pengguna: **Bahasa Indonesia**; komentar kode: **Bahasa Inggris**.
- Urutan siklus UI: Build → Plan → Auto (dua mode lama tidak bergeser).
- `npm run check` hijau sebelum tiap commit; `test:related` untuk file yang berubah.

## Review Focus

- **Tab lama mengirim `{mode:'auto'}` tanpa `modeChosen`** → harus tetap tersimpan sebagai `build` (bukan Auto). Diuji di Task 3.
- **`state.json` lama berisi `mode:'auto'`** saat load → harus jadi `build` + `modeNotice`, bukan Auto. Diuji di Task 3.
- **`isMode('autopilot')` benar tapi `normalizeMode('auto')` legacy** → `normalizeMode` harus memetakan `auto` ke `build`, `autopilot` ke `autopilot`. Diuji di Task 1.
- **UI: engine OpenCode tidak menawarkan `autopilot` / engine Claude menawarkannya** dengan benar lewat `capsFor`. Diuji di Task 5.
- **Claude melaporkan `permissionMode:'auto'` sendiri** → `appModeFromCli('auto')` harus `autopilot` agar mode tidak "balik" ke build. Diuji di Task 4.

```js
export const MODES = Object.freeze(['build', 'plan', 'autopilot']);
export const DEFAULT_MODE = 'build';

/** A value the app may store as-is. Anything else is refused, never coerced on the write path. */
export const isMode = (value) => value === 'build' || value === 'plan' || value === 'autopilot';

/** Display/back-compat normalization: legacy and unknown values read as Build (never as a weaker permission). */
export function normalizeMode(value) {
  return value === 'plan' ? 'plan' : value === 'autopilot' ? 'autopilot' : 'build';
}

/** What Claude Code's `--permission-mode` / `set_permission_mode` get: Plan, auto-edit for Build, or the classifier. */
export function claudePermissionMode(mode) {
  return mode === 'plan' ? 'plan' : mode === 'autopilot' ? 'auto' : 'acceptEdits';
}

/** Claude Code reports its CLI name (`default`, `acceptEdits`, `auto`...) - the app maps it back to its own vocabulary. */
export function appModeFromCli(mode) {
  if (mode === 'plan' || mode === 'dontAsk') return 'plan';
  // `auto` is only ever sent by us (--permission-mode auto): read it back as our Auto, or the mode would flip to Build.
  if (mode === 'auto') return 'autopilot';
  // A CLI started outside the app (default/acceptEdits) is shown as Build; settings are not rewritten from it.
  return 'build';
}
```

Biarkan `migrateMode` **tidak berubah** (baris 25-30) — komentar `manual / acceptEdits / auto -> build` tetap benar.

```js
export function permissionConfig(mode, user = {}) {
  // Build = auto-edit: files may be written automatically; shell and network still ask. Plan is read-only: edit and
  // shell are denied outright, and even a user "allow" cannot open them (mergePermission's plan rule). Auto
  // (autopilot) = like `opencode --auto`: shell and network are allowed too, but explicit user denies still win and
  // the `read` tool is untouched (so OpenCode's own .env ask stays). 'dontAsk' stays deny-all as a defence in depth.
  const base =
    mode === 'dontAsk' || mode === 'plan' ? { edit: 'deny', bash: 'deny', webfetch: 'deny' }
    : mode === 'autopilot' ? { edit: 'allow', bash: 'allow', webfetch: 'allow' }
    : { edit: 'allow', bash: 'ask', webfetch: 'ask' }; // build (and any legacy mode normalized to it)
  // The user's own rules are kept, never loosened by the mode: see mergePermission (src/opencode-bin.js).
  return mergePermission(base, user, mode);
}
```

`src/acp-session.js` `OPENCODE_CAPS.modes` (baris 146) → `Object.freeze(['build', 'plan', 'autopilot'])`, dan perbarui komentar baris 144-145 menyebut Auto.
